v2.2: native shell proof and a clearer license

June 4, 2026 - by Matthew Kissinger

Sheep Dog Sim is still a browser game first. The important part of v2.2 is that the same built web game now has proof that it can boot inside native shells without rewriting the game into a different engine.

The first Windows Electron proof boots the packaged dist/ output from an app protocol, starts a real Classic run, and records renderer behavior for WebGL and WebGPU. The first Android Capacitor proof boots a debug APK on an emulator and reaches gameplay on WebGL. That is not a store release yet. It is the first useful native handoff.

Follow-up desktop work has now turned the Electron proof into a real Windows distributor path with installer, portable, and unpacked outputs. Packaged WebGL and WebGPU both boot and play on the Windows proof host, including native resize, fullscreen, input, audio, storage, Worker health, and WebSocket checks.

Current claim: Windows desktop packaging is proven enough for a local Steam depot dry-run. Not current claim: public Steam, Google Play, App Store, or signed Windows release readiness.

What changed legally

v2.2 is also the forward-only license transition. Current source code is AGPL-3.0-or-later. Current non-code assets are CC BY-SA 4.0. Earlier releases retain the license terms recorded in their historical artifacts.

In plain terms: the game is still free to play, study, fork, and modify. If you host or distribute a modified version, keep visible attribution and publish the corresponding source. The running game now shows a source notice on the about page, start/loading flow, and HUD.

What this unlocks

  • A Windows desktop package path ready for local Steam depot dry-run work.
  • A mobile proof path for Android WebView behavior without changing the core game architecture.
  • A cleaner public repo story: readable source, explicit asset terms, and honest native readiness gates.

What still has to be proven

Signed Windows builds, installer/uninstaller QA, Steam metadata, store screenshots, controller expectations, cloud-save decisions, and real-device mobile proof are still future work. WebGPU also stays evidence-driven: if a shell or browser cannot create a stable WebGPU device, the WebGL path remains the fallback.
