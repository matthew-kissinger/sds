# Sheep Dog Sim v2.6.3 Play Start Performance Release Notes

Status: release source copy for the v2.6.3 web beta hotfix.

Sheep Dog Sim v2.6.3 removes the long, glitchy delay between pressing Play and controlling the dog. Every public scene now starts through one visible loading transaction, with stable gameplay arriving in seconds instead of the previous 8-34 second range measured on the affected paths.

## Changed

- The public web game now uses the stable WebGL renderer for consistently fast starts. WebGPU remains available through an explicit developer query for diagnostics.
- Long music tracks stream on first playback instead of blocking startup on full-track download/decoding or opening an abort-and-retry metadata request.
- Only the selected dog, flock, scene, and music are prepared for the chosen round.
- Sandbox and local two-player modes use the same visible, recoverable loading transaction as solo play.
- The characterized CPU boid path has less per-frame allocation and duplicated neighbor/fence/obstacle work. Five thousand sheep remains a supported CPU stress tier; higher 5K/25K/100K GPGPU experiments stay in the separate R&D lab rather than changing deterministic multiplayer.

## Fixed

- Play accepts only one start transaction, so repeated clicks cannot overlap scene swaps or music transitions.
- Partial scene graphs are no longer rendered while startup work is still mutating them.
- Removed duplicate pregame dog/flock construction and duplicate audio catalogs.
- Mobile solo modes no longer ask for a second confirmation above 1,000 sheep.
- Sandbox deep links no longer build an unused scene behind setup before Start.
- Local versus fences, flock construction, and leaderboard eligibility now match the selected local mode.

## Validation

- Current-build state-asserted production-preview matrices passed 26/26 desktop cold configurations, 26/26 phone/touch configurations, 9/9 sandbox/local configurations, 4/4 gamepad smoke configurations, and 4/4 warm-navigation configurations. Same-page restart also passed.
- Desktop cold median was 2.557 seconds to proven movement and 4.586 seconds to a stable two-second frame window. Phone/touch median was 2.563 seconds and 4.575 seconds. HTTP-warm median was 1.642 seconds to movement; same-page restart took 929 ms.
- Every accepted case verified the active scene, mode, selected dog, expected live flock, renderer, requests, audio, browser errors, and real movement from the selected input. The worst post-playable task was 125 ms.
- The explicit WebGPU diagnostic reproduced 14.301 seconds to input and 21.482 seconds to settled gameplay, validating its removal from public settings.
